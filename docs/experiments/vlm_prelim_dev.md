# 예비 실험: dev 학습 없는 기준값 (2026-11-12, 1회 실행)

복지 안내 영상 dev 8개(55분)에서, 학습하지 않은 상태의 기존 방식(main)과 VLM 인코더를 비교했습니다. 비교 설정은 결과 보기 전에 [vlm_model_plan.md](vlm_model_plan.md) 「11/14 예비 실험」에 고정했고, 그대로 한 번 실행했습니다. 전체 표: [vlm_prelim_dev_tables.md](vlm_prelim_dev_tables.md), 질의별 결과: [rows.json](../../ai/experiments/vlm_model/results/prelim_dev/rows.json).

## 요약

**같은 화면 검색 절차에서 인코더만 CLIP → Qwen3-VL-Embedding-2B로 바꾸면**, 1위 구간 적중(IoU ≥ 0.3)이 5% → 25%, 화면 글자로 찾는 질의에서는 6% → 34%로 올랐습니다. 특징 추출은 영상 1분당 1.32초로 시간 한도(1.5초) 안입니다.

### 핵심 표: 기존 인코더(CLIP) vs VLM 인코더 — 화면 검색, 학습 없음

두 방식은 같은 프레임(2초마다 1장), 같은 구간 규칙(유사도 평활화 → 상위 8칸 → 가장 긴 연속 구간)을 쓰고 인코더만 다릅니다.

| | 다국어 CLIP (`clip-ViT-B-32-multilingual-v1`) | **Qwen3-VL-Embedding-2B** |
|---|---|---|
| 전체 (n=80): R@1 IoU≥0.3 / IoU≥0.5 | 5% (4) / 1% (1) | **25% (20) / 20% (16)** |
| 전체: R@3 / R@5 | 11% / 12% | **38% / 38%** |
| V 화면 (n=38): R@1 IoU≥0.3 | 8% (3) | **39% (15)** |
| V 화면 글자 (n=32): R@1 IoU≥0.3 | 6% (2) | **34% (11)** |
| S 말 (n=42): R@1 IoU≥0.3 | 2% (1) | 12% (5) |
| 사용자 질문 (n=18): R@1 IoU≥0.3 | 0% (0) | 6% (1) |
| 1위 구간 시작 ±5초 | 6% | **24%** |
| 특징 추출 (영상 1분당) | 0.6초 | 1.32초 (한도 1.5초) |
| 질의당 응답 중앙값 / 95% | 6 / 17 ms | 29 / 59 ms |
| 무작위 기준선 R@1 IoU≥0.3 | 5% | 5% |

- 질의별로 보면 Qwen만 맞힌 질의 17개, CLIP만 맞힌 질의 1개입니다.
- 다국어 CLIP은 무작위 기준선(5%)과 같은 수준입니다. 0단계 실측에서 CLIP 계열이 한국어 화면 글자를 읽지 못한 것(합성 화면 R@1 3~13%)과 같은 결과입니다.

### 기존 main 방식과의 비교

| 방식 | 전체 R@1 IoU≥0.3 | S 말 | V 화면 | V 화면 글자 | 사용자 질문 | R@3 |
|---|---|---|---|---|---|---|
| B1 자막 검색 (MiniLM) | 38% (30) | 45% | 29% | 25% | 17% | 52% |
| B2 구간 검색 CLIP 버전 (NLLB 번역 + Moment-DETR) | 8% (6) | 5% | 11% | 12% | 11% | 11% |
| **B3 main 서비스 결합** | **40% (32)** | 45% | 34% | 31% | 17% | 55% |
| 화면 검색 Qwen3-VL-Embedding-2B (학습 없음) | 25% (20) | 12% | **39%** | **34%** | 6% | 38% |
| 무작위 기준선 | 5% | 5% | 5% | 5% | 7% | – |

- **B2(지금 서비스의 구간 검색 모델, CLIP 버전)는 8%로 무작위(5%)와 거의 같습니다.** 이 모델을 VLM 버전으로 다시 학습하는 이유입니다(QVH 다운로드가 끝나는 대로 시작).
- **B3(main)의 점수는 대부분 MiniLM 자막 검색에서 나옵니다.** main 서비스는 한국어 자막이 있으면 자막 검색 결과만 쓰고, 자막이 없을 때만 번역+Moment-DETR로 넘어갑니다. dev에서는 자막 있는 영상 7개에서 B3 = B1이고, 말 없는 dev06에서만 B2입니다.
- **화면 검색(VLM)은 V 질의에서 main보다 높고(39% vs 34%), S 질의에서는 낮습니다(12% vs 45%).** 둘 중 하나라도 맞힌 질의는 43/80개(B3만 23, VLM만 11)입니다. 이 값은 두 결과 중 맞는 쪽을 항상 고를 수 있다고 가정한 **탐색적 상한**이고 실제 방식이 아닙니다. 다만 둘을 결합하는 방식(N3, 11/20~22에 dev에서 결합 규칙 결정)에 기대할 여지가 있다는 근거입니다.

### 참고값 (판정·제안서 본문에는 쓰지 않음)

| 방식 | 전체 | S | V | V 화면 글자 | 비고 |
|---|---|---|---|---|---|
| 화면 검색 Qwen3-VL-Emb **1280×720** | 41% | 29% | 55% | 59% | 특징 추출 영상 1분당 4.06초로 **시간 한도 초과** |
| 자막 검색 Qwen3-VL-Emb 텍스트 | 54% | 62% | 45% | 41% | MiniLM 유지 결정에 따라 참고만 |

- **입력 해상도의 영향이 큽니다**: 같은 모델에서 640×360 → 1280×720로 바꾸면 화면 글자 질의가 34% → 59%입니다. 작은 신청서 글자를 읽으려면 해상도가 중요하다는 뜻이지만, 지금은 시간 한도를 넘습니다. 화면 일부만 높은 해상도로 보는 방법 등은 다음 후보로 기록만 합니다.
- 자막 검색에서도 Qwen3-VL-Emb 텍스트가 MiniLM보다 높았습니다(54% vs 38%). 결정대로 자막 검색은 MiniLM을 유지하고, 이 값은 참고로만 둡니다. 이 방식의 질의당 95% 응답(1,176 ms)은 영상마다 첫 질의에서 자막 창 임베딩을 계산한 시간이 포함된 값입니다. 서비스라면 분석 때 미리 계산합니다.

### 사용자 질문은 훨씬 어렵습니다

AI 초안 질의(n=62)와 사용자 질문(n=18)으로 나누면 모든 방식이 사용자 질문에서 크게 떨어집니다(B3 47% → 17%, 화면 검색 VLM 31% → 6%).

- AI 초안 질의는 화면·자막을 본 AI가 썼기 때문에 영상 속 표현과 가깝고, 그래서 점수가 높게 나왔을 가능성이 큽니다.
- 사용자 질문은 제목만 보고 쓴 구어체 질문(「엄마폰에 앱 깔았는데 뭐 눌러야돼」)이라 실제 사용에 더 가깝습니다. **발표·제안서에는 두 수치를 함께 보여 주는 것이 맞습니다.**

### 정답 없음 질의

정답 없음 질의(22개)와 정답 있는 질의의 1위 점수 분포가 거의 겹칩니다(예: 화면 검색 VLM 중앙값 0.434 vs 0.449, MiniLM 0.682 vs 0.676). 점수 임계값만으로는 「결과 없음」을 가려내기 어렵다는 뜻입니다. 임계값은 계획대로 11/20~22에 dev에서 정합니다.

## 사용자 질문 중 영상에 답이 없는 비율

dev 사용자 질문 24개 중 **6개(25%)는 영상에 답이 없습니다.** 답이 있는 18개 중 3개는 부분 답입니다(나이 조건만 나오는 등).

| 사용자 유형 | 정답 없음 / 전체 |
|---|---|
| 가족 대신 알아보는 사람 | **3 / 6** |
| 부모 | 1 / 3 |
| 어르신 | 1 / 6 |
| 청년 | 1 / 5 |
| 기타 | 0 / 4 |

- 「가족 대신」 질문이 절반(3/6) 답이 없었습니다. 안내 영상은 대부분 **본인이 신청하는 과정**만 보여 주고, 대리 신청은 다루지 않습니다.
- 애매한 질문은 1/5, 구체적인 질문은 5/19가 답이 없어, 애매함보다는 질문 내용(대리 신청, 신청 기간 등)이 영향을 줬습니다.

### 공식 데이터(두 API)로 답할 수 있는지

판정 기준은 위 부분 답 규칙과 같습니다(직접 쓸모 있는 정보 → 답할 수 있음, 일부만 → 부분, 주제만 비슷 → 없음). AI가 판정 초안을 만들고 **검수자가 확인**했습니다(1개 수정: dev03 「손주 봐줄 사람 신청 내가 해도 되나」 부분 → 없음). 근거 인용 18개는 API 원문과 대조해 모두 확인했습니다. 원본 데이터: [official_dev.json](../../ai/experiments/vlm_model/results/official_dev.json)(2026-11-12 호출), 판정과 근거 문장: [official_judgments_dev.json](../../ai/experiments/vlm_model/results/official_judgments_dev.json).

| 영상 | 사용자 질문 (영상에 답 없음) | 중앙부처복지서비스만 | 공공서비스(혜택) 정보만 | **두 API 합침** | 근거 |
|---|---|---|---|---|---|
| dev01 | 「엄마 대신 기초연금 인터넷으로 신청 되나요」 | 없음 | 부분 | **부분** | 공공서비스 「신청방법」: 복지로 온라인 신청 가능 → 인터넷 신청은 답, 대리 신청 여부는 없음 |
| dev03 | 「아이돌봄 신청 화면 어디서 눌러요?」 | 없음 | 부분 | **부분** | 공공서비스 「신청방법」·「온라인신청사이트URL」(idolbom.go.kr): 신청 경로·사이트는 있음, 화면의 메뉴·버튼 위치는 없음 |

| 집계 (6개) | 답할 수 있음 | 부분 | 없음 | 해당 서비스 없음 |
|---|---|---|---|---|
| 중앙부처복지서비스만 | 1 | 0 | 4 | 1 |

| **두 API 합침** | 1 | 3 | 2 | 0 |

- 영상에 답이 없던 사용자 질문 6개 중 **4개는 공식 데이터로 적어도 일부 답할 수 있었습니다**(답할 수 있음 1, 부분 3). 영상과 공식 정책정보를 함께 보여 주는 구조(제안서의 Policy-to-Scene Grounding)가 필요한 근거입니다.
- 두 API는 서로 보완합니다. 공공서비스(혜택) 정보로만 답할 수 있던 질문이 3개(신청방법·신청 사이트가 있음)이고, 두 API 모두로 답할 수 있던 질문이 1개(신청 기간)입니다. 중앙부처복지서비스만으로 답할 수 있던 질문은 없었습니다. 중앙부처복지서비스는 선정기준이 자세하지만 신청방법이 비어 있는 서비스가 있었고, 구직급여는 아예 없었습니다.
- **대리 신청(「엄마 대신」, 「남편 대신」, 「아빠 … 대신」, 「손주 … 내가 해도 되나」)은 두 API 모두 직접 답하지 못했습니다.** 영상에도 없고 공식 데이터에도 없는 정보라, 서비스에서는 문의처(예: 기초연금 1355, 통신요금감면 1523)를 함께 안내하는 방식이 필요합니다.
- 「이거 아직 신청 되는거에요?」처럼 **신청 기간** 질문은 영상(제목에만 「마감」)으로는 답할 수 없고 공식 데이터로는 답할 수 있었습니다. 영상 게시일과 정책 기준일을 구분해 최신 공식 정보를 우선 안내해야 한다는 제안서 2-다의 근거입니다.
- 화면 위치 질문(「어디서 눌러요」, 「~하는 화면」)은 공식 데이터에 신청 사이트 주소까지만 있고 화면 안의 위치는 없어 「부분」입니다. 이 부분은 영상 장면 검색이 맡을 몫입니다.

## 검수와 한계

- **검수**: dev 102개(AI 초안 78 + 사용자 질문 24)를 검수자 1명이 모두 검수했고, **수정은 0건**입니다(문구·구간·유형·정답 없음 전환 모두). 부분 답 3개는 초안 메모의 「부분 답변」을 검수자가 확인한 뒤 표시했습니다. eval_v2 때도 수정 0건이었습니다.
- 정답 구간은 AI가 프레임·자막을 보고 정한 초안입니다. 경계 오차가 1~2초 있을 수 있습니다(시트 시각 표시 오류는 발견 뒤 수정).
- 질의 80개, 영상 8개로 작습니다. 차이가 몇 개(±3개 안팎)이면 우연일 수 있습니다. 위 핵심 비교(4 → 20개, 화면 글자 2 → 11개)는 이보다 훨씬 큽니다.
- dev는 이후 결합 규칙·임계값을 정하는 데 다시 씁니다. 최종 판정은 11/24 test 1회로 합니다.
- 실험 설정: 프레임 2초마다 가운데 1장, 640×360(참고 1280×720), Qwen3-VL-Embedding-2B 특징 추출은 CPU 디코딩 + GPU 전처리 + 묶음 16([vlm_speed_opt.md](vlm_speed_opt.md)), 질의 지시문 「Retrieve images or video frames relevant to the user's query.」, RTX A5000. 질의 실행 중 GPU 최대 할당 9.37 GiB(평가 스크립트에 모든 모델을 함께 올린 값).
- 재현: `python ai/experiments/vlm_model/prelim_eval.py --out ai/experiments/vlm_model/results/prelim_dev` → `prelim_report.py`.
