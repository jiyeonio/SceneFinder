# VLM 설명문 검색: 서비스 경로 끔·켬 비교 (dev → test)

설계와 미리 정한 기준은 [docs/design/vlm_search.md](../design/vlm_search.md)(커밋 e944ecb, dev 비교 전)에 있습니다. 이 문서는 그 기준을 바꾸지 않고 적용한 결과입니다.

- **질의는 AI 초안을 사람이 검수한 것(human_reviewed)입니다.** dev 60개(S 27 = 말 내용 15 + 화면 묘사 12, V 33), test 58개(S 31 = 말 내용 15 + 화면 묘사 16, V 27)
- **test는 이번이 두 번째 사용입니다.** 첫 번째는 임베딩 비교([embedding_compare.md](embedding_compare.md)의 「test 확인」)
- 검색은 실제 서비스 경로 `POST /api/search`(top_k 5)로 보냄. 「끔」= `CAPTION_SEARCH_ENABLED=0`(지금 서비스), 「켬」= 같은 코드에 `=1`
- 지표는 개수: IoU≥0.3 / IoU≥0.5 / R@3(NMS IoU 0.5 뒤 상위 3개 중 IoU≥0.3) / 1위 시작 ±5초. 잡음 수준은 ±3개
- 스크립트: `ai/experiments/vlm_service_compare/run.py`, `report.py`. 결과 JSON은 저장소 밖(`~/scenefinder_eval/vlm_service/`)

## 결론

- **dev에서는 `zscore_max`·확장 2초가 기준을 모두 통과했지만, test에서는 불통과입니다.** (그래도 켜기로 한 결정과 근거는 아래 「결정」)
  V는 크게 올랐지만(IoU≥0.3 3 → 13, R@3 5 → 19), S의 IoU≥0.3이 2개 줄어 기준(1개 넘게 줄지 않음)을 넘었고, 말 내용 S의 IoU≥0.3도 2개 줄어 기준(줄지 않음)을 어겼습니다.
- 줄어든 폭(−2)은 잡음 수준(±3) 안이고, 같은 S에서 R@3은 +4, 말 내용 S R@3은 +2로 올랐습니다. 다만 기준은 미리 정한 대로 적용하므로 **판정은 불통과**입니다.
- test 결과를 보고 결합 후보를 다시 고르면 test가 선택에 쓰이므로, 다른 후보(`subtitle_first` 등)는 이 test로 다시 재지 않았습니다.

## 결정 (2026-10-17): 서비스에서 켬

- **사전 기준 S IoU≥0.3 −1 허용 대비 −2로 미달.** 전체 IoU≥0.3 20 → 28, V 3 → 13, S R@3 19 → 23을 근거로 켬.
- 말 내용 질의 자막 우선 규칙은 **새 test 세트로 추후 검증 예정.**
- 적용: 코드 기본값은 꺼짐(`CAPTION_SEARCH_ENABLED=0`) 그대로 두고, 서버의 `backend/.env`에만
  `CAPTION_SEARCH_ENABLED=1`, `CAPTION_FUSION=zscore_max`, `CAPTION_SPAN_EXPAND_SEC=2`를 설정함.

## 여러 영상 동시 요청 시 INDEXED 지연 (켠 뒤 발견, 2026-10-17 수정)

**발견**: 서비스에서 켠 뒤, 짧은 영상도 「분석 중」이 예전보다 오래 걸림. 서버 로그와 DB 시각(`videos.created_at`·INDEXED 갱신, `video_captions.started_at`·`finished_at`)으로 확인한 원인:

- `POST /api/search/multi`는 한 요청에서 분석할 영상(최대 5개)의 `run_indexing`을 같은 `BackgroundTasks`에 넣고, FastAPI(Starlette)는 이를 **한 스레드에서 차례로** 실행함
- 처음 구현은 `run_indexing`이 INDEXED 뒤 설명문 대기열 차례와 생성이 끝날 때까지 기다렸음 → 같은 요청의 다음 영상은 **앞 영상 설명문이 끝나야 다운로드를 시작**
- 예: 약 16분 영상(설명문 482장, 232초) 다음 순서의 짧은 영상이 INDEXED까지 279초(분석 자체는 3.8초). 앞 영상 설명문 끝 시각 + 분석 시간이 INDEXED 시각과 초 단위로 맞음
- Whisper CPU 전환·GPU 메모리 부족은 없었음(Qwen 로드 1회, 언로드 0회). 설명문 생성은 `_AI_LOCK`을 쓰지 않아 잠금 대기가 원인은 아님
- 위 test의 「INDEXED가 늦어지지 않음」은 영상을 하나씩 따로 요청해서 확인한 것이라 이 경우를 잡지 못했음

**수정**: `run_indexing`은 INDEXED 뒤 설명문 대기열에 넣고 바로 끝남. 설명문은 작업 스레드 1개가 차례로 만들고, 끝나면 그 영상 파일도 지움.
기존 규칙은 그대로: 대기 최대 `CAPTION_QUEUE_MAX`개, 사용자가 연 영상 우선, 넘치면 PENDING(분석 작업이 파일 바로 삭제),
Whisper GPU 메모리 부족 시 설명문 모델을 내리고 Whisper 먼저, 서버 재시작 때 PROCESSING은 FAILED.
대기열이 가득 찬 상태에서는 사용자가 연 영상도 PENDING이 되는 것도 예전과 같음.

**검증** (`ai/experiments/vlm_service_compare/multi_video_check.py`): 로컬 영상 5개를 「한 요청」처럼 한 스레드에서 차례로 분석(다운로드만 로컬 복사로 바꿈), 끔·켬 각각 새 프로세스.
통과 기준은 실행 전에 **영상마다 켬이 끔보다 5초 넘게 늦지 않음**으로 정함. 시간은 요청 시작 기준(초, DB를 0.5초마다 조회).

|---|---|---|---|---|
| HsV9CMmEvFo (15분) | 20.8 | 20.4 | −0.4 | 242.0 |
| x54thOO7NHU (3.5분) | 26.3 | 25.5 | −0.8 | 288.8 |

- **통과** (최대 +1.7초). 늘어난 1~2초는 설명문 생성과 Whisper가 GPU를 같이 쓰는 시간으로 보임
- 처음 구현이었다면 두 번째 영상부터 앞 영상 설명문이 끝난 뒤 시작하므로, 두 번째 영상 INDEXED가 약 247초(242 + 5)였을 것(추정, 다시 재지 않음)
- 「내려받은」 영상 파일 용량: 끔은 동시에 최대 31.3 MB(분석 중인 1개), 켬은 설명문 대기 때문에 최대 119.2 MB. 끝난 뒤 둘 다 0 MB(파일 모두 삭제됨)
- 수정 후 8000을 다시 띄워 검색 1번 확인(caption_status READY, 1위 설명문 654–660초)

## 확인한 것과 주의할 점

- **응답 시간이 켬에서 더 짧은 이유**: 설명문 덕분이 아니라, 켬 경로는 자막 창 임베딩을 파일로 저장해 다시 쓰고(`data/processed/subtitles/{id}.minilm.pt`) 끔 경로(`predict_moments_fusion`)는 요청마다 자막 창을 다시 인코딩하기 때문입니다. 설명문 검색 자체가 더하는 시간은 이 차이 안에 묻혀 따로 재지 않았습니다.
- **GPU 메모리 부족 (test 1차 실행 중 발견, 수정 커밋 42b84f8)**: 설명문 생성 뒤 Qwen 모델과 torch 캐시가 GPU에 남아, 다음 영상의 Whisper가 CUDA out of memory로 실패하고 그 프로세스의 자막 생성이 모두 CPU로 바뀌었습니다(INDEXED 16.7초 → 289초).
  끔·켬 백엔드 두 개가 한 GPU(24GB)를 같이 쓴 평가 환경 탓이 크지만, 서비스에서도 일어날 수 있어 고쳤습니다(생성 뒤 캐시 비움, 메모리 부족이면 설명문 모델을 내리고 GPU로 다시 시도, 그래도 안 되면 그 영상만 CPU).
  1차 실행은 **지표를 계산하기 전에 멈췄고**(켬 쪽 자막이 CPU로 만들어져 비교가 섞임), 고친 뒤 test를 처음부터 다시 돌렸습니다. 그래서 위 test 결과는 1번만 계산한 것입니다.
- **자막이 분석할 때마다 조금씩 다름**: 같은 영상을 끔(8000)에서 다시 분석한 직후와 켬(8001)에서 다시 분석한 뒤의 끔 결과가 test 14개 질의에서 달랐습니다(같은 GPU·같은 Whisper 설정). 그래서 test의 「끔」은 켬과 **같은 자막 파일로 다시 잰 값**을 씁니다. dev는 설명문 생성 때 만든 자막 파일 하나로 끔·켬을 모두 쟀습니다.
- 응답 시간은 같은 질의를 2번 더 보낸 중앙값이고, 끔과 켬은 서로 다른 프로세스(같은 GPU)입니다.
- 설명문 생성 시간(켬, 한 번에 1개): 3~15분 영상에서 36~220초. 15분 강의 영상(451장)이 가장 오래 걸림.
