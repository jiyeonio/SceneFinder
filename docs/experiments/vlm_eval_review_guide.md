# 복지 평가셋 검수 안내 (팀원 3명, 11/12~13)

> **정답 구간의 시작·끝은 반드시 영상을 재생해서 직접 확인하세요. AI 초안의 시작·끝은 실제 영상과 최대 1~2초 어긋날 수 있습니다.**

검수 목록: [vlm_eval_review.tsv](vlm_eval_review.tsv) (묶음·영상별 진행 상황과 예상 시간). 계획: [vlm_model_plan.md](vlm_model_plan.md) 3절.

## 순서 (꼭 지켜 주세요)

1. **1단계: 직접 질문 쓰기 (AI 초안을 보기 전)**
   - 내 묶음의 영상을 하나씩 훑어보고, **영상마다 1~2개씩** 실제 사용자가 물어볼 법한 말투로 질문을 쓰고 정답 구간을 찍습니다.
   - 예: 「기초연금 신청할 때 뭐 가져가요?」, 「아이돌봄 신청 버튼 어디 있어요」, 「월세 지원 나이 몇 살까지예요」
   - 라벨링 도구에서 저장하면 자동으로 「직접 작성」(`human_written`)으로 표시됩니다.
2. 묶음의 모든 영상에 직접 쓴 질문이 1개 이상 생기면 서버 담당에게 알립니다. 서버 담당이 `review_bundles.py merge --bundle N`을 실행해 AI 초안을 합칩니다. 직접 쓴 질문이 없는 영상이 하나라도 있으면 이 명령이 거부됩니다.
3. **2단계: AI 초안 검수**
   - 도구를 새로고침하면 「AI 초안」 질의가 보입니다(「미검수만 보기」로 걸러 볼 수 있음).
   - 합칠 때 「먼저 볼 것」 메모(Whisper 오인식, 애매한 경계, 구간이 두 개인 질의)가 함께 출력됩니다. 서버 담당이 내 묶음 부분을 전달합니다. 질의 내용이 들어 있어 1단계 전에는 보지 않습니다.
   - 초안 작성 자료(프레임 시트)의 시각 표시가 실제보다 1~1.5초 빨랐던 것을 발견해 고쳤습니다. 에이전트가 대부분 원본 프레임·자막 시각으로 경계를 다시 잡았지만, **시작·끝이 1~2초 어긋난 초안이 있으면 고쳐 주세요.**
   - 하나씩 ▶로 구간을 재생해 보고, 맞으면 「검수 완료」를 누릅니다. 틀리면 「편집」으로 고친 뒤 「수정 저장 + 검수 완료」를 누릅니다. 질의 자체가 이상하면 삭제합니다.

## 접속과 실행

라벨링 도구는 서버 안에서만(127.0.0.1) 열리므로, 내 컴퓨터에서는 **포트 포워딩**으로 접속합니다. 묶음별 포트: 묶음 1 → 8771, 묶음 2 → 8772, 묶음 3 → 8773.

### 1) 서버에서 도구 실행 (내 묶음 번호로)

서버에 접속한 터미널에서 실행하고, 검수하는 동안 터미널을 닫지 않습니다.

    cd ~/scenefinder
    # 예: 묶음 1 (묶음 2·3은 숫자 세 곳과 포트를 바꿈)
    python tools/labeler/server.py --labels ai/experiments/vlm_model/labels/bundle1.json \
        --youtube-list ai/experiments/vlm_model/labels/bundle1_videos.tsv \
        --videos /nfs/team/data/scenefinder_vlm/eval_videos_bundle1 --port 8771

### 2-A) VS Code로 접속 (추천)

1. VS Code에서 Remote-SSH로 서버에 접속합니다(왼쪽 아래 `><` 아이콘 → Connect to Host).
2. 위 1)의 명령을 VS Code 터미널에서 실행합니다.
3. 아래 패널의 **PORTS(포트)** 탭 → **Forward a Port(포트 전달)** → 내 묶음 포트(예: `8771`) 입력. 도구를 실행하면 자동으로 추가되기도 합니다.
4. 내 컴퓨터 브라우저에서 `http://127.0.0.1:8771` (내 묶음 포트)을 엽니다. PORTS 탭의 지구본 아이콘을 눌러도 됩니다.

### 2-B) ssh 명령으로 접속

내 컴퓨터 터미널(Windows는 PowerShell)에서 실행합니다. `<계정>`, `<서버주소>`는 평소 서버에 접속할 때 쓰는 값입니다.

    ssh -L 8771:127.0.0.1:8771 <계정>@<서버주소>

이 접속을 유지한 채 그 창에서 위 1)의 명령을 실행하고, 내 컴퓨터 브라우저에서 `http://127.0.0.1:8771`을 엽니다.

### 안 될 때

- 「address already in use」: 같은 포트로 도구가 이미 떠 있습니다. 다른 터미널에 떠 있는 도구를 쓰거나 끈 뒤 다시 실행합니다.
- 브라우저에서 연결 거부: 서버에서 도구가 실행 중인지, 포워딩한 포트와 도구의 `--port`가 같은지 확인합니다.
- 영상이 안 나옴: 영상 정보 칸의 재생 방식을 「로컬 파일」로 바꿉니다(회사·학교 망에서 YouTube 임베드가 막힌 경우).

### 사용할 때 알아 둘 것

- 내 묶음 영상만 보입니다. 처음에는 YouTube 임베드로 재생되고, 영상 정보 칸의 재생 방식에서 「로컬 파일」(서버에 받아 둔 720p mp4)로 바꿀 수 있습니다. 시간은 둘이 같습니다.
- 영상 키(dev05 등)는 이미 정해져 있으니 바꾸지 마세요.
- 저장할 때마다 서버의 파일에 바로 씁니다. 묶음마다 파일이 따로라 세 명이 동시에 해도 됩니다.

## 질의 유형

| 유형 | 뜻 | 확인 방법 |
|---|---|---|
| S 말로 설명됨 | 내레이션이 **말하는 내용**을 찾는 질의 (조건, 금액, 기간, 주의사항, 팁) | 화면을 안 보고 소리만 들어도 구간을 고를 수 있어야 함 |
| V 화면에만 보임 | **화면**을 봐야 찾을 수 있는 질의 (신청서 칸, 버튼, 메뉴 단계, 서류 목록, 팝업) | 신청서·버튼·서류 이름처럼 화면 글자로 찾을 수 있으면 「화면 글자로 찾을 수 있음」 체크 |
| 정답 없음 | 이 영상에 말로도 화면으로도 **없는** 내용 | 영상 전체를 봤을 때 정말 없으면 「검수 완료」 |

- **자막만 언급 구간**(V 질의만): 내레이션은 그 내용을 말하지만 화면에는 안 나오는 구간입니다. 예를 들어 1:10에 「구비서류를 첨부하세요」라고 말하지만 화면은 만화이고, 실제 서류 첨부 화면은 4:20에 나오는 경우 1:10 부근이 자막만 언급 구간입니다. 시작·끝을 찍고 「자막만 언급 구간 추가」를 누릅니다. 없으면 비워 둡니다.
- 정답 구간은 그 내용이 **이어서 나오는 전체**를 잡습니다. 같은 내용이 여러 번 나오면 구간을 여러 개 추가합니다(판정은 가장 많이 겹친 구간 기준).
- 말이 없는 영상(dev06, test02)은 S 질의를 쓰지 않습니다.

## AI 초안 검수에서 볼 것

- 구간 경계: 시작·끝이 2초 넘게 어긋나면 고칩니다(`,` `.`로 0.1초씩 이동).
- S 질의가 실제로는 화면 묘사가 아닌지(소리만으로 찾을 수 있는지). 화면 묘사면 유형을 V로 바꿉니다.
- 정답 없음 질의가 실제로는 영상에 나오지 않는지.
- 메모(note)에 AI가 근거로 본 시트·자막 줄이 적혀 있습니다.

## 시간

예상 시간은 검수 목록의 `예상_1단계_분`, `예상_2단계_분` 열에 있습니다. 1단계는 영상 길이의 0.6배(훑어보기)와 직접 질문 2개 × 4분, 2단계는 AI 초안 1개당 2분(자막만 언급 구간이 있으면 +1분), 정답 없음 1개당 1분으로 계산했습니다.
