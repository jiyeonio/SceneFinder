# CLIP 화면 검색을 세 번째 신호로 쓰기 (dev)

지금 서비스 검색(자막 MiniLM + 설명문 e5, [vlm_service_compare.md](vlm_service_compare.md))에 화면 신호를 하나 더 붙이면 나아지는지 봅니다.
후보는 다국어 CLIP 프레임 유사도([eval_v2.md](eval_v2.md)의 (c))와 Moment-DETR(자막 없는 영상의 기존 경로)입니다. **서비스 코드는 바꾸지 않은 실험이고, dev 영상 6개만 씁니다.**

**이 문서의 「미리 정한 것」 절은 결과를 보기 전에 정해 커밋했습니다(2026-10-22).** 결과를 본 뒤 바꾸면 그 사실과 이유를 결과 절에 적습니다.

## 미리 정한 것

### 질의 범위: 넓은 장면 / 특정 순간

- **넓은 장면**: 정답 구간 합이 **영상 길이의 10% 이상이거나 60초 이상**인 질의. 영상의 상당 부분에 이어지는 상태·활동(예: 「돌판 위에서 스테이크를 굽는 장면」)
- **특정 순간**: 그 밖의 질의. 짧은 동작·장면(예: 「달걀말이가 찢어진 장면」)
- 기존 dev 검수 질의 60개는 이 규칙으로 넓은 장면 1개(#156), 특정 순간 59개라, dev 영상에서 넓은 장면 질의 **14개(#231–244)를 AI 초안으로 추가**함(`source: ai_draft`).
  5초 간격 프레임과 자막을 보고 만들었고 경계는 5초 단위 대략값. 사람 검수 전이라 **넓은 장면 결과는 검수 후 다시 계산해야 확정**
- 질의별 분류는 [clip_third_signal_scope.tsv](clip_third_signal_scope.tsv)

### 지표

- IoU ≥ 0.3 (1위 구간), R@3 (NMS IoU 0.5 뒤 상위 3개 중 IoU ≥ 0.3) — 기존과 같음
- **hit-in-GT (새 지표)**: 1위 구간의 가운데 시각이 정답 구간(여러 개면 그중 하나) 안에 있는지. 넓은 장면은 정답이 길어 IoU가 낮게 나오기 쉬우므로 「맞는 곳을 가리켰는가」를 따로 봄
- 묶음: 넓은 장면 / 특정 순간 × S / V, 그리고 전체. 개수로 셈. 잡음 수준 ±3개([caption_batch_compare.md](caption_batch_compare.md))보다 큰 차이만 의미 있게 봄

### 비교 방식 (모두 영상마다 top 5, 서비스와 같은 겹침 제거: 짧은 쪽의 50% 이상 겹치면 뺌)

- **(a) 현재 서비스**: 자막(MiniLM) + 설명문(e5), `zscore_max`·설명문 앞뒤 2초 확장. `backend/services/captions.py`의 `fused_search`와 같은 규칙을 실험 코드로 다시 구현하고, 결과가 같은지 확인
- **(b) a + 다국어 CLIP**: `clip-ViT-B-32-multilingual-v1`로 한국어 질의를 그대로 벡터로 만들어 2초 단위 CLIP feature와 코사인 비교
  - 후보: eval_v2 (c)와 같은 규칙(유사도 평활화 → 상위 8칸 → 연속 구간을 (길이, 평균 유사도) 순으로), 그다음 유사도 높은 2초 칸
  - 후보 점수 = 그 구간 칸들의 평활화 유사도 평균, z-score = (후보 점수 − 영상 전체 칸 평균) ÷ 칸 표준편차
- **(c) a + Moment-DETR**: 서비스와 같은 NLLB 번역 → `predict_moments_hybrid`(top 10) 후보, z-score는 그 후보 점수들로 계산
- **세 신호 합치기 (b·c 공통)**
  - z-score를 쓸 수 없는 경우(후보·칸 5개 미만 또는 표준편차 0.01 미만)는 서비스와 같음
  - (a)가 자막 우선으로 바뀌는 경우(자막이나 설명문의 z를 못 쓰는 경우)는 (a) 순서를 그대로 두고 세 번째 신호는 맨 뒤에 붙임(1위 후보가 될 수 없음)
  - 그 밖에는 각 신호 1위 후보의 z가 큰 순서로 신호를 줄 세워 1위를 정하고, 2위부터 그 순서대로 번갈아 채움. 세 번째 신호의 z를 못 쓰면 맨 뒤
  - 구간: 자막은 서비스 보정(시작 2초 앞당김, 최소 6초), 설명문은 앞뒤 2초 확장, CLIP·Moment-DETR는 후보 구간 그대로
- 주의: z-score의 기준 분포가 신호마다 다름(자막·설명문은 창 수백~수천 개, CLIP은 2초 칸 수백 개, Moment-DETR는 후보 10개). 후보가 적으면 1위의 z가 작게 나오므로 Moment-DETR는 1위가 되기 어려운 구조

### 실행 환경

- **GPU를 쓸 수 없는 상태라 CPU로 실행**함(서버 재시작 뒤 컨테이너에서 GPU가 보이지 않음). 서비스는 GPU에서 돌므로, 임베딩 계산의 작은 수치 차이 때문에 **점수가 근소한 후보끼리는 순위가 서비스와 다를 수 있음**
- 설명문·자막 파일은 지금 서비스 서버의 파일(`data/processed/`)을 읽기만 함. CLIP feature는 eval_v2 실험 때 서비스의 `build_feature`로 만든 파일(`~/scenefinder_eval/results_v2_whisper_turbo_b8/`)
- 「자막 있는 영상에도 CLIP feature를 만들 때 늘어나는 분석 시간」은 GPU 복구 후 따로 잼
