# 실사용 짧은 질의 평가

지금까지 평가 질의는 「케이스 두 개 위아래로 겹쳐 충전 단자 비교」처럼 장면을 자세히 묘사한 문장이었습니다. 실제 사용자는 「골 넣는 장면」처럼 짧게 칠 가능성이 높아서, 짧은 질의로 따로 평가합니다.

## 한계 (먼저 읽어 주세요)

- **질의는 AI가 영상 제목·분야만 보고 작성했고, 정답 구간은 AI가 프레임(과 자막)을 보고 지정했습니다. 사람 검수는 없습니다.**
- **완전한 「보지 않고 작성」은 아닙니다.** 질의를 쓴 AI는 같은 대화에서 이미 dev 영상 6개의 5초 간격 프레임을 봤고([clip_third_signal.md](clip_third_signal.md)의 넓은 장면 질의 작성), 12개 영상의 기존 평가 질의와 실험 결과도 알고 있었습니다. 이 영향을 줄이려고 질의에는 제목에 나온 말과 일반적인 동작만 썼습니다.
- 정답 구간은 5초 간격 프레임 기준이라 경계가 대략값이고, 「빠짐없이 전부」 찍으려 했지만 짧은 장면은 놓쳤을 수 있습니다.

- **GPU를 쓸 수 없는 상태라 CPU로 실행**했습니다. 서비스(GPU)와 임베딩 계산의 작은 수치 차이가 있어 **점수가 근소한 후보끼리는 순위가 서비스와 다를 수 있습니다**
- (a)는 실험 코드로 다시 구현한 것이고, 같은 프로세스에서 서비스 함수 `captions.fused_search`와 29개 모두 결과가 같았습니다
- 방식: (a) 현재 서비스(자막 MiniLM + 설명문 e5, `zscore_max`·확장 2초), (b) Moment-DETR 단독(NLLB 번역 + `predict_moments_hybrid`), (c) 자막만(서비스 구간 보정), (d) 설명문만(앞뒤 2초 확장). 모두 영상마다 top 5

### 해석

1. **짧은 질의에서는 지금 서비스(a)도 1위가 맞는 곳을 가리킨 경우가 29개 중 12개(거의 전체인 3개를 빼면 26개 중 9개)입니다.** 묘사형 질의로 잰 결과([vlm_service_compare.md](vlm_service_compare.md))보다 낮게 보이지만 질의·정답 기준이 달라 직접 비교할 수는 없습니다
2. **설명문만(d)이 서비스(a)보다 hit-in-GT가 2개 많습니다(14 vs 12).** 자막 1위가 z-score에서 이겨 틀린 곳을 가리킨 경우가 있었습니다(#256 「양념장 만들기」, #257 「두부 굽는 장면」: 자막 1위 152초·5초, 설명문 1위는 정답 안). 반대로 #255 「완성된 방」은 자막이 맞혔습니다. 차이는 잡음 수준(±3) 안입니다
3. **자막만(c)은 짧은 질의에 약합니다(hit 2/29).** 「골 넣는 장면」처럼 짧은 질의는 해설 문장과 단어가 잘 겹치지 않습니다
4. **Moment-DETR(b)는 hit-in-GT는 낮지만 R@3·IoU≥0.3이 가장 높습니다(13·7).** 1위 구간이 길어(예: 156–881초, 0–352초) 긴 정답과 잘 겹치기 때문이고, 정답이 영상의 30% 이상인 질의에서 IoU≥0.3이 5/7입니다. 반대로 구간이 너무 길어 가운데가 정답 밖으로 나가는 경우가 많습니다(#263 156–881초)
5. **IoU≥0.3은 (a)·(c)·(d) 모두 0~1개입니다.** 1위 구간이 6~10초라 짧은 질의의 정답(여러 구간에 걸치거나 수십 초 이상)과 겹치는 비율이 작습니다. [clip_third_signal.md](clip_third_signal.md)의 넓은 장면 결과와 같은 문제입니다

## 미리 정한 것

### 후보 (모두 영상마다 top 5, 겹침 제거는 서비스와 같이 짧은 쪽의 50% 이상)

- **(a) 현재 서비스**: 자막 + 설명문, `zscore_max`·설명문 앞뒤 2초 확장 (비교 기준)
- **M1 칸 나눠 채우기**: 1·2·3위 = [설명문 1위, Moment-DETR 1위, 자막 1위]. 이미 고른 구간과 겹치면 같은 신호의 다음 후보. 4·5위는 같은 순서로 한 바퀴 더. 자막이 없는 영상은 자막 칸을 건너뜀. z-score 비교 없음
  - 구간: 설명문 앞뒤 2초 확장, Moment-DETR 그대로, 자막은 서비스 보정(시작 2초 앞당김, 최소 6초)
- **M2 구간 이어붙이기**: (a)와 같은 순서로 고르되, 1위가 설명문이면 그 구간을 이어붙여 넓힘
  - 설명문 1위 창의 2초 칸들에서 시작해, 좌우 이웃 2초 칸(설명문 1개짜리 창)의 z-score가 **1위 창의 z − δ 이상**이면 계속 붙임. z는 그 영상의 설명문 창 전체 점수 기준(서비스와 같음)
  - 최대 길이 120초, 붙인 뒤 앞뒤 2초 확장
  - δ는 두 값: **M2-0.5 (δ = 0.5), M2-1.0 (δ = 1.0)**

### 해석

1. **구간 이어붙이기(M2)는 구간을 거의 넓히지 못했습니다.** 1위가 이어붙인 구간인 질의에서 길이(앞뒤 2초 확장 포함) 중앙값이 6~10초, 최대 16초로, 지금 서비스(설명문 2~6초 창 + 4초)와 큰 차이가 없습니다. 이웃 2초 칸의 z-score가 1위 창보다 빠르게 떨어져 δ = 0.5·1.0 안에 드는 칸이 적었습니다. 세트 B에서 1위 구간이 (a)와 달라진 질의는 M2-1.0 기준 4개였지만 지표는 하나도 바뀌지 않았습니다
2. **칸 나눠 채우기(M1·M3)는 짧은 질의에서 R@3을 올리지만 기존 세트에서 떨어집니다.** 세트 A에서 R@3이 +2~+4, 세트 B에서는 +5(4 → 9)였지만, dev 특정 순간에서 세 지표가 2~3개, 넓은 장면에서 hit-in-GT가 2개 줄어 미리 정한 조건에 걸렸습니다. Moment-DETR 1위가 2위 칸을 차지하면서, 묘사형 질의에서 자막·설명문 2위였던 정답 후보가 밀려난 것으로 보입니다
3. **세트 B에서 M1·M3의 R@3 +5는 미리 정한 판정 대상이 아닙니다.** 세트 A로 고른 후보만 세트 B로 확인하기로 했으므로, 세트 B 결과를 보고 M1으로 바꾸지 않습니다. 짧은 질의에서 Moment-DETR 칸이 상위 3개에 들어가는 효과는 있어 보이나, 기존 세트에서의 손해와 함께 새 세트로 다시 봐야 합니다
4. 짧은 질의의 IoU≥0.3이 낮은 문제(1위 구간이 정답보다 훨씬 짧음)는 이번 후보들로 해결되지 않았습니다
