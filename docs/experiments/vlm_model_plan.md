# 기존 SceneFinder 모델의 VLM 버전: 계획과 비교 기준 (결과 보기 전 고정, 2026-11-11)

목표는 **기존 모델을 VLM으로 바꾸는 것**입니다. 모델 구조와 학습 코드는 그대로 두고, 특징 추출기만 VLM으로 바꿔 다시 학습합니다.

| 역할 | 지금 (main) | VLM 버전 (이 브랜치 `vlm/model`) |
|---|---|---|
| 구간 검색 | **SceneFinder 구간 검색 모델 (CLIP 버전)**: Moment-DETR, CLIP ViT-B/32 영상·텍스트 특징, 한→영 번역 뒤 검색 | **SceneFinder 구간 검색 모델 (VLM 버전)**: 같은 Moment-DETR 구조·학습 코드·학습 데이터. 특징만 Qwen3-VL-Embedding-2B. 한국어 질의를 번역 없이 넣음 |
| 자막 검색 | 파인튜닝 MiniLM | **그대로 유지** (파인튜닝 MiniLM) |
| 화면(프레임) 검색 | 없음 | Qwen3-VL-Embedding-2B (2초마다 프레임 1장). LoRA 파인튜닝은 여기에만 |
| 결합 | 구간 검색 + 자막 검색 (`predict_moments_fusion`) | 구간 검색(VLM) + 자막 검색(MiniLM) + 화면 검색(VLM). 규칙은 dev에서만 정함 |

- 코드·결과 폴더 이름: 구간 검색 CLIP 버전 `mr_clip`, VLM 버전 `mr_vlm`, 화면 검색 `frame_vlm`(LoRA 적용본 `frame_vlm_lora`).
- 서비스 코드(`backend/`, `frontend/`)는 이 단계에서 건드리지 않습니다. 모델이 검증되면 별도 승인을 받아 연결합니다.
- 참고만 한 브랜치: `feature/vlm-search` (머지 안 함). 거기서 가져온 교훈: 비교 기준을 결과 전에 고정, dev에서만 설정을 고르고 test는 한 번만, 결과를 본 뒤 추가한 방식은 「탐색적」으로 표시, 시간·메모리 한도를 성능과 따로 판정.

## 1. 0단계 확인 결과 (2026-11-11)

### GPU·저장 공간

RTX A5000 24GB(측정 때 사용 0MiB). 홈 디스크는 여유 12GB뿐이라, 영상·특징·체크포인트는 모두 NFS `/nfs/team/data/scenefinder_vlm/`(여유 1.7TB)에 둡니다. 저장소에는 넣지 않습니다.

### 인코더 실측

스크립트: [encoder_probe.py](../../ai/experiments/vlm_model/encoder_probe.py), 결과: [encoder_probe.json](../../ai/experiments/vlm_model/results/encoder_probe.json)

합성 복지 화면 30종(제목처럼 크게 쓴 글자 / 서류 목록 안 작은 글자)을 놓고 한국어 질의로 맞는 화면을 1위에 고른 비율(R@1, 무작위 3%)을 쟀습니다. 질의는 화면 글자 그대로 쓴 것과 바꿔 말한 것(예: 「기초연금 신청서」 → 「노인 연금 신청 양식」) 두 종류입니다. 속도는 평가 영상 battery_lecture(15분)에서 2초마다 뽑은 640×360 프레임 450장으로 쟀습니다.

| 모델 | 크기 | 라이선스 | 글자 그대로 (제목 / 목록) | 바꿔 말함 (제목 / 목록) | 영상 1분당 특징 추출 | 질의 1개 | GPU 최대 |
|---|---|---|---|---|---|---|---|
| 다국어 CLIP B/32 | 0.15B | Apache-2.0 | 3% / 7% | 0% / 7% | 0.06초 | 3.7ms | 0.9GiB |
| SigLIP2-base-224 | 0.38B | Apache-2.0 | 10% / 10% | 10% / 3% | 0.06초 | 4.7ms | 1.2GiB |
| SigLIP2-so400m-384 | 1.14B | Apache-2.0 | 13% / 3% | 7% / 7% | 0.32초 | 9.8ms | 2.7GiB |
| **Qwen3-VL-Embedding-2B** | 2.13B | Apache-2.0 | **83% / 40%** | **30% / 17%** | 0.93초 | 27ms | 5.5GiB |

측정하지 않은 후보: Qwen3-VL-Embedding-8B(Apache-2.0, 8.1B, bf16 약 17GB라 서비스와 함께 올리기 어려움), GME-Qwen2-VL-2B(Apache-2.0, 공식 지원 언어 영어·중국어), jina-embeddings-v4(Qwen Research License, 비상업이라 제외).

- SigLIP2는 텍스트 쪽이 다국어여도 **이미지 속 한국어 글자는 거의 읽지 못했습니다.** 복지 안내 영상의 신청서 칸·버튼·서류 목록을 찾아야 하므로 Qwen3-VL-Embedding-2B로 정했습니다.
- 한 모델(5.5GiB)로 구간 검색 VLM 버전의 특징과 화면 검색을 같이 처리합니다. 2초마다 뽑은 프레임 특징을 두 곳에서 같이 쓰므로 추출은 한 번만 합니다.
- 한계: 합성 이미지 30장, 1회 측정이라 모델 선택 근거로만 씁니다. Qwen3-VL-Embedding은 공식 코드와 같은 방식(system 지시문 + 생성 프롬프트 뒤 마지막 토큰 hidden state, L2 정규화)으로 직접 구현했습니다. 첫 작업에서 sentence-transformers 공식 경로와 출력이 같은지 확인합니다.

### QVHighlights 원본과 재학습 비용

- 서버에 있는 QVHighlights 특징(CLIP·SlowFast·PANN, 10,148개 영상 전부)은 영어 CLIP 공간이라 VLM 버전에는 못 씁니다. 원본 영상은 예시 1개뿐입니다.
- 원본 `qvhilights_videos.tar.gz`(143.7GB)는 UNC 서버에서 받습니다(연결당 약 33KB/s, 32개 연결 합계 약 1.04MB/s → 약 38시간). [qvh_download.sh](../../ai/experiments/vlm_model/qvh_download.sh)로 2026-11-11 06:43에 시작했습니다. **11/14까지 다 받지 못하면 받은 앞부분만 풀어서 먼저 학습합니다**([qvh_extract.sh](../../ai/experiments/vlm_model/qvh_extract.sh)). 이때 쓴 영상 수와 목록을 결과에 기록합니다.
- 공개된 다른 특징(Moment-DETR 원본, Lighthouse의 CLIP·SlowFast, SG-DETR의 InternVideo2)은 모두 영어 텍스트 공간이라 한국어 질의를 번역 없이 넣는다는 목표에 맞지 않습니다.
- 예상 시간: 특징 추출 약 6.6시간(클립 10,148개 × 75프레임), 영어 질의 한국어 번역 약 1시간, 학습 1회 1~1.5시간(CLIP 버전 200 epoch 기록 63분).

## 2. 학습 설정

### 구간 검색 모델 VLM 버전

- 코드: `ai/vendor/moment_detr`의 학습 코드를 그대로 쓰고, 특징 폴더와 차원(`v_feat_dim`, `t_feat_dim`)만 바꿉니다. 나머지 설정은 CLIP 버전 체크포인트(`scratch_clip_align`)의 `opt.json`과 같습니다(seed 2018, 200 epoch, bsz 32, lr 1e-4, `contrastive_align_loss`, `ctx_mode video_tef`, `clip_length 2`).
- 영상 특징: 2초마다 가운데 프레임 1장의 Qwen3-VL-Embedding-2B 임베딩(CLIP 버전과 같은 간격).
- 질의 특징: 질의 토큰별 마지막 hidden state(CLIP 버전처럼 토큰 단위) vs 마지막 토큰 1개. **QVH val에서 골라** 복지 dev에는 영향이 없게 합니다.
- 학습 데이터: QVHighlights train. 영어 질의를 한국어로 번역한 버전을 만들어 세 가지로 학습합니다: 영어만 / 한국어만 / 영어+한국어. 번역본은 파일로 고정해 커밋하고, 번역 모델과 설정을 기록합니다.
- 고르기: 세 가지 중 하나를 **복지 dev**로 고르고, 나머지는 부록에 둡니다.

### 구간 검색 VLM 버전 자동 파이프라인 세부 규칙 (2026-11-11, 결과 전 고정)

[qvh_next.sh](../../ai/experiments/vlm_model/qvh_next.sh)가 영상 특징 추출 뒤 자동으로 돌립니다. test는 돌리지 않습니다.

- 학습 데이터: QVH 특징이 있는 영상의 질의만 쓰고, CLIP 재현과 VLM 버전 모두 같은 질의 집합을 씁니다(개수는 결과 초안에 기록).
- 번역: 로컬 Qwen3-VL-4B-Instruct, greedy, 프롬프트 고정([qvh_translate.py](../../ai/experiments/vlm_model/qvh_translate.py)). 한국어 질의는 qid에 1,000,000을 더해 영어 질의와 구분합니다.
- 질의 특징 두 종류: 질의 토큰별 hidden state(최대 32개, tok) / 마지막 토큰 1개(pooled, 검색 임베딩과 같음). **영어+한국어로 둘 다 학습하고 한국어 val MR-full-mAP가 높은 쪽을 고른 뒤**, 그 종류로 영어만·한국어만을 학습합니다.
- 체크포인트 선택: CLIP 재현은 영어 val, VLM 버전은 세 가지 모두 **한국어 val**(목표 언어)로 고릅니다(5 epoch마다 평가, MR-full-mAP 최고). VLM 버전은 영어 val로도 따로 평가합니다.
- CLIP 재현: CLIP 버전(2026-09-29)과 같은 코드·옵션·seed 2018, 특징은 원래 CLIP·텍스트 특징 그대로.
- 복지 dev 평가: 서비스 predict_moments와 같은 추론(영상 전체 입력, TEF, L2 정규화). 서비스의 보정 단계(자막·CLIP 시작점 보정)는 넣지 않아 **모델 자체**를 비교합니다(서비스 보정까지 넣은 값은 예비 실험의 B2). CLIP 재현은 NLLB 번역 영어 질의, VLM 버전은 한국어 질의를 그대로 넣습니다.
- 시험 실행(2026-11-11): QVH 영상 93개, 5 epoch로 1~12단계 전체를 끝까지 돌려 동작만 확인했습니다(숫자는 의미 없음).

### 화면 검색 (Qwen3-VL-Embedding-2B, LoRA) — 2026-11-12 갱신, 학습 전 고정

**목표**: 예비 실험에서 가장 약했던 **사용자 질문의 화면 검색**(dev R@1 IoU≥0.3 6%, 1/18)을 올리는 것. 무학습(zero-shot)과 LoRA 적용본을 모두 보고합니다.

- 학습 쌍 (한국어 질의, 프레임). 질의 말투를 두 가지로 섞습니다.
  - (a) QVHighlights train: 영어 질의의 한국어 번역 ↔ 정답 구간 안 프레임. 같은 영상의 정답 밖 프레임을 어려운 오답으로 씀
  - (b) 학습용 복지 영상(평가 채널이 아닌 공식 채널, 아래 「분리」 원칙) 프레임 + 그 구간 자막을 Qwen3-VL-4B-Instruct(로컬)가 보고 만든 질의
    - (b-1) 화면 글자 기반 질의: 신청서 칸·버튼·서류 이름이 들어간 질의
    - (b-2) **사용자 말투 질문(필수)**: 어르신·청년·아이 키우는 부모·가족 대신 알아보는 사람 등 사용자 유형을 섞고, 짧고 일상적인 말투, 행정용어와 화면 글자를 그대로 쓰지 않음, 약 1/4은 애매하게. 정답은 그 프레임·구간
    - (b-3) **제목 먼저 방식**(평가 사용자 질문과 같은 순서): 생성 모델이 영상 제목·정책만 보고 사용자 질문을 먼저 쓰고, 그다음 같은 모델이 영상 프레임·자막을 보고 답이 되는 구간을 찾음. 답이 없으면 버림. 평가의 사용자 질문은 내용을 모르고 쓴 질문이라, 프레임을 보고 쓴 질문만으로는 말투·내용 분포가 다를 수 있기 때문입니다
  - AI-Hub 017(한국어 텍스트-비디오-사운드) 원천 영상은 지금 없어서 쓰지 않습니다. 팀이 확보하면 추가하고 기록합니다.
- **평가 질의 유출 방지**: 생성 프롬프트의 예시 문장은 새로 쓰고, 평가셋의 질의(AI 초안·사용자 질문)를 예시로 쓰지 않습니다. 생성된 질의 중 평가 질의와 같거나 매우 비슷한 것(글자 3-gram 자카드 ≥ 0.8)은 자동으로 뺍니다. 평가 사용자 질문은 다른 생성기(별도 에이전트, 제목만 봄)로 만들었고, 학습 질의는 로컬 Qwen3-VL-4B-Instruct로 만듭니다.
- 학습 설정(첫 실행 값, 바꾸면 기록): LoRA rank 16·alpha 32·dropout 0.05, 언어 모델 attention(q·k·v·o) 대상, 학습률 1e-4, InfoNCE(묶음 안 오답 + 같은 영상 어려운 오답), 온도 0.05, 1~2 epoch, seed 42. 화면 특징 추출 설정(640×360, 2초마다 1장)은 무학습과 같게 유지합니다.
- **고르는 기준(dev, 결과 보기 전 고정)**: dev 사용자 질문(정답 있음 18개)의 R@1 IoU≥0.3 + R@3 개수 합이 가장 큰 설정. 단, dev AI 초안 질의(62개)의 R@1 IoU≥0.3이 무학습보다 3개 넘게 떨어지면 탈락. 사용자 질문은 18개뿐이라 ±3개는 잡음 수준으로 보고, 보고서에 그렇게 적습니다.
- 자막 검색은 MiniLM을 그대로 쓰고, LoRA는 화면 검색에만 적용합니다.
- 참고 비교(판정에 쓰지 않음): 자막 검색에서 MiniLM vs Qwen3-VL-Embedding-2B(텍스트만)를 dev에서만 비교합니다.

#### 실행 세부 (2026-11-12, LoRA·결합 결과 보기 전 고정)

- **학습 영상**: 평가 채널이 아닌 공식 기관 채널 24개(채널 검색 결과에서 구독자·업로드 수·핸들로 공식 판단, [lora_candidates.py](../../ai/experiments/vlm_model/lora_candidates.py))에서 정책 키워드 + 「신청·방법·조회」 제목 후보 162개 → 채널당 최대 2개, 신청·조회 화면 제목 우선, 탐방·브리핑·행사 제목 제외 → **20개(16개 채널, 120분)**: [vlm_lora_train_videos.tsv](vlm_lora_train_videos.tsv). 평가 영상 제목과 3-gram 자카드 ≥ 0.4면 재업로드 의심으로 제외. 자막은 모두 Whisper(서비스 설정, 업로더 자막 조회는 YouTube 요청을 줄이려고 생략).
- **질의 생성** ([lora_make_data.py](../../ai/experiments/vlm_model/lora_make_data.py)): 자막을 이어 10~16초 장면으로 나누고, 장면 앞·뒤 프레임 2장 + 자막으로 (b-1) 화면 글자 질의 1개, (b-2) 사용자 말투 질문 2개(사용자 유형 6가지를 돌려 가며, 장면 절반은 두 번째 질문을 애매하게 → 사용자 질문의 약 1/4). (b-3) 제목·정책만 보고 질문 6개 → 장면 목록(자막·화면 설명)에서 답 장면 고르기, 없으면 버림. 같은 영상 안 중복, 화면 글자를 60% 넘게 베낀 사용자 질문, 평가 질의와 3-gram 자카드 ≥ 0.8은 제거. 결과는 labels/lora_train_pairs.jsonl로 커밋.
- **LoRA 변형 2개 × epoch 2개 = 후보 4개**: mix(복지 + QVH train 한국어 번역 질의 2,000개) / welfare(복지만), 각각 epoch 1·2 저장. 나머지 설정은 위 그대로(r16, α32, dropout 0.05, q·k·v·o, lr 1e-4 코사인·warmup 5%, InfoNCE τ 0.05, 묶음 16, seed 42). 어려운 오답: 복지는 같은 영상의 정답에서 20초 넘게 떨어진 칸, QVH는 같은 영상 정답 밖 칸. **peft를 설치하지 않고**(원래 저장소 가상환경 공유) LoRA를 직접 구현([lora.py](../../ai/experiments/vlm_model/lora.py)). 학습 전 어댑터(B=0)가 무학습 결과와 질의별로 똑같음을 확인.
- 고르기는 위 「고르는 기준」 그대로([lora_select.py](../../ai/experiments/vlm_model/lora_select.py)).

### N3 결합 규칙 격자 (2026-11-12, 결과 보기 전 고정)

[combo_dev.py](../../ai/experiments/vlm_model/combo_dev.py). 후보 풀의 구간마다 s_sub(MiniLM, 겹치는 자막 창 최고 점수, 영상 안 z) · s_frame(화면 검색 평활 점수 구간 평균, 영상 안 z) · s_mr(N1 후보와 IoU ≥ 0.5면 1/(1+순위)) 가중합.
- rerank: 풀 = B1 상위 K + N1 상위 3 / fusion: 풀 = 여기에 N2 상위 3 구간 추가
- 격자: K ∈ {5, 10}, w_frame ∈ {0, 0.25, 0.5, 1, 2}, w_mr ∈ {0, 0.5} (w_sub = 1, 자막 없는 영상은 0) → rerank 20개, 화면 점수는 무학습·고른 LoRA 각각
- **화면 검색 구간 시작 앞당기기(2026-11-12 추가, 결과 전 고정)**: fusion 풀에 들어가는 N2(화면 검색) 구간의 시작을 shift ∈ {0, 2, 4}초 앞당김(0초 미만은 0, 끝은 그대로). 자막(B1) 구간은 이미 서비스 보정(2초 앞당김·최소 6초)이 들어가 있어 그대로 두고, N1 구간도 그대로. rerank 풀에는 N2 구간이 없어 해당 없음 → fusion 60개, 합계 80개 × 화면 점수 2종
- 고른 규칙에 대해 보조 지표(시작 ±5초, 앞 0~5초)도 함께 보고(고르기에는 쓰지 않음)
- 고르기: dev 전체 R@1 IoU≥0.3 최대 → R@3 → 시작 ±5초. 질의 80개에 맞춘 값이라 dev 숫자는 낙관적이고, test 1회로 확인합니다.
- 정답 없음 임계값(**결과: 적용 안 함**, 2026-11-12 사용자 결정 — 아래 「정답 없음 처리 결정」): 고른 규칙의 1위 점수로, dev 정답 없음 질의 22개와 정답 있음 질의를 가르는 값(정답 있음 질의를 10% 넘게 버리지 않는 범위에서 정답 없음을 가장 많이 거르는 값).

### VLM 장면 재판별 (제안서 3-가-③, 2026-11-12 추가, 결과 보기 전 고정)

생성형 VLM(로컬 Qwen3-VL-4B-Instruct)이 N3 상위 K개 후보 구간의 프레임과 그 구간 자막을 보고 「질의에 답하는 장면인지 / 화면에 실제로 나오는지」를 판단해 다시 순위를 매깁니다([vlm_rejudge.py](../../ai/experiments/vlm_model/vlm_rejudge.py)).

- **판단 점수**: 생성하지 않고 첫 응답 토큰의 「예」와 「아니오」 logit만 비교해 P(예) = softmax(예, 아니오)[예] (질의당 한 번의 forward, 후보 K개를 한 묶음으로).
- **프레임**: 후보 구간마다 3장(시작+1초, 가운데, 끝−1초에 가장 가까운 2초 칸 프레임, 640×360, 특징 추출과 같은 디코딩) + 구간과 겹치는 자막(최대 200자). 프레임 수는 지연 때문에 3장 하나로 고정.
- **후보 (2 × 2 × 2 = 8개 + 재판별 없음)**:
  - K ∈ {3, 5}
  - 프롬프트 A(답하는가): 「이 장면(화면과 자막)이 질문에 직접 답합니까? 예 또는 아니오로만 답하세요.」
  - 프롬프트 B(화면에 실제로 나오는가): 「질문이 찾는 내용이 이 장면의 **화면에 실제로 보입니까**? 자막에서 말로만 언급되면 아니오입니다. 예 또는 아니오로만 답하세요.」
  - 결합: vlm_only = P(예) 순서 / mix = 0.5 × N3 순위 점수(1위 1 → K위 0, 등간격) + 0.5 × P(예)
  - 「재판별 없음」(N3 그대로)도 후보 → 나아지지 않으면 N3를 그대로 고름
- **고르기(dev)**: R@1 IoU≥0.3 최대 → R@3 → 시작 ±5초. 후보 수를 적게 둔 것은 질의 80개 과적합을 줄이려는 것이고, dev 숫자는 낙관적입니다.
- **함께 보고(고르기에는 안 씀)**:
  - 사용자 질문(18개) R@1·R@3, 시작점 보조 지표
  - **자막에만 언급되는 오검색**: (1) 검수에서 「자막에만 나오는 구간」이 표시된 dev 질의 7개 중 1위가 그 구간과 겹치는(IoU ≥ 0.3) 비율, (2) V(화면) 질의 중 1위가 오답이면서 화면 검색 후보와 겹치지 않고 자막 후보에서만 온 비율. 둘 다 질의 수가 적어 참고용.
- **지연**: 질의당 ① 기본 결과(N3) 지연, ② VLM 확인 완료 지연(①+재판별)을 p50·p95로 따로 잽니다(같은 A5000, 모델은 미리 올려 둠, 프레임은 색인 때 미리 저장한 2초 칸 프레임을 읽는다고 가정해 디코딩 시간 제외 — 서비스도 색인 때 프레임 저장). ②의 p95가 1초를 넘으면 서비스는 **「기본 결과 즉시 표시 → VLM 확인 후 순위 갱신」 비동기 방식**을 전제로 하고, 판정의 응답 시간 한도(1초)는 ①에 적용합니다.
- **test 최종 후보 규칙(결과 전 고정)**: dev에서 고른 재판별 설정이 N3보다 R@1 IoU≥0.3이 **3개 넘게** 높으면 최종 후보 = N3+VLM 재판별, 아니면 N3. test에는 두 설정을 모두 고정해 1회 실행하고, 채택 판정은 최종 후보로만 합니다(다른 하나는 참고).
- **변경(2026-11-12, 결과 본 뒤 — 시간 한도 때문, 사용자 결정)**: 고른 N3 풀에 N1 상위 3개가 들어 있어(가중치 0) 영상마다 특징을 두 번(무학습·LoRA) 뽑아야 해 특징 추출이 약 2.6초/영상 1분으로 한도(1.5초)를 넘었습니다. **N3 = 자막 상위 5 + 화면 검색 상위 3(N1 후보 없음)**으로 정의를 바꾸고 나머지 설정(LoRA 화면 점수, 가중치, 4초 앞당기기)은 그대로 둡니다. VLM 재판별은 같은 후보 8개·같은 규칙으로 새 풀에서 다시 골랐습니다(K5·A·mix, N3 41 → 43, +2) → 규칙(3개 넘게)에 따라 **최종 후보 = N3**, N3+VLM 재판별은 test에서 함께 돌려 참고로 보고합니다.
